## 背景与现状

现有切块方案（`document_service.py:22-51` + `config.py:50-51`）：

- `RecursiveCharacterTextSplitter`，`CHUNK_SIZE=800`、`CHUNK_OVERLAP=120`
- 分隔符 `["\n\n", "\n", "。", "；", "，", " ", ""]`（定长 + 标点递归切）
- 注解：`citation.py` 的 `extract_chapter`（正则 `第X章`）/ `extract_clause`（`第X条` 或 `\d+(\.\d+){1,3}`）

**与给排水规范条文的不匹配**：定长 + 按标点切会拆散一条条文、或把多条条文拼进一块；`extract_clause` 匹配"块内第一个多级编号"可能命中正文里"见 3.1.2"这类引用，条款号不准；分隔符无表格结构，表格会被拆散。

## 条文结构需求（用户给定）

- 结构：`1 标题`（一级）→ `1.X 二级标题` → `1.X.X 条文正文`（切块单元）
- 正文前有**前言、目次、Contents**（一级标题级），不进向量库
- 条文内部表格编号 `1.X.X-A`（= 条文 1.X.X 的第 A 个表），**不切块**，内容并入所属条文
- 条文正文里有"见表 1.X.X-A"指引文字，保留在正文
- 每个 chunk 元数据带：所属文件 + 页码

## 已确认决策

1. **`1 标题` / `1.X 二级标题` 只作元数据**（不单独切块，挂到所属条文块，避免只含标题的噪声块）。
2. **超长条文二次切分**（正文含表格累计超阈值时二次切，子块共享同一 clause 元数据）。
3. **前言/目次/Contents 彻底跳过**（不入库、不建向量）。

## 切块方案设计

### 结构识别（行首正则 + 状态机）

| 结构 | 识别规则 | 处理 |
| --- | --- | --- |
| 前言 / 目次 / Contents | 行匹配 `前言`/`目次`/`Contents` | 彻底跳过 |
| `1 标题` | `^\d+\s+\S+`（数字+空格+标题，非 `1.1`） | 更新 `chapter`，不切块 |
| `1.X 二级标题` | `^\d+\.\d+\s+\S+` | 更新 `section`，不切块 |
| `1.X.X 条文正文` | `^\d+\.\d+\.\d+` | 切块起点 |
| `1.X.X-A` 表格 | `表?\s*\d+\.\d+\.\d+-[A-Z]` | 并入所属条文，不切块 |

### 切块算法（状态机）

维护 `chapter / section / clause / page` 四游标：

1. 前言/目次/Contents → 跳过态，直到下一个正文 `1 标题` 或 `1.X.X`；
2. `1 标题`/`1.X` → 只更新 `chapter`/`section`，不产生 chunk；
3. `1.X.X` → 开新条文 chunk，累计正文 + 后续表格内容（表格转 Markdown 保行列），直到下一个 `1.X.X` 或文档结束；
4. 条文内"见表 1.X.X-A"指引 → 原样保留。

### 元数据（每 chunk）

```python
{
  "document_id": ..., "title": ..., "code": ..., "version": ..., "category": ...,
  "chapter": "1 总则", "section": "1.1", "clause": "1.1.1",
  "page": "5-6",  # 页码范围（跨页记 "5-6"，单页记 "5"）
  "chunk_index": 3, "has_table": True,
}
```

### 超长二次切分

- 超阈值（**500 字符**）用 `RecursiveCharacterTextSplitter` 二次切，子块共享 `clause/chapter/section` 元数据，`chunk_index` 递增，**overlap = 0**（语义单元不重叠）。

### 页码跟踪

页码来自 OCR 阶段（渲染第几页出的文本就带第几页）。**需回改 OCR 方案**：`ocr_service.extract_pdf_text` 返回带「页码 + 结构」的内容，非纯文本。条文跨页记**页码范围**（如 `5-6`）。

## 已确认参数

1. 二次切分阈值：**500 字符**。
2. 跨页页码：记**范围**（如 `5-6`）。
3. 二次切分 overlap：**0**（不重叠）。

## 条文所属规范返回分析（已确认能正确返回）

**结论**：规范归属靠 chunk metadata，与切块方法无关，新方案不破坏它。

链路（全程保留 `title/code/version/document_id`）：
1. `document_service._store_chunks`（`document_service.py:59-71`）把文件级字段写入每个 chunk metadata；
2. `vector_store_service.search` 原样返回 metadata；

**落地底线**：`_store_chunks` 继续把文件级字段写进每个 chunk（含二次切分子块）。
