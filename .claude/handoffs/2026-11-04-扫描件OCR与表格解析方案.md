## 背景与问题

实际使用中发现：给排水规范 PDF 多为**扫描件（图片无文字层）**，最大可达 60+ MB，且页面内**文字 + 表格混合**、有**斜向两行水印**。当前系统无法处理：

1. `document_service._load_file` 用 `PyMuPDFLoader` 抽文字层（`document_service.py:33-39`），扫描件 `get_text()` 为空 → chunks 为空 → 报「文档解析后无有效内容」。
2. `MAX_FILE_SIZE = 20MB`（`config.py:72`），60MB 文件直接在上传时被拒。
3. 水印会被 OCR 识别进去，污染索引（样例水印：斜向两行「住房城乡建设部信息公开 / 浏览专用」，灰度 230–250，正文灰度 <189，可阈值分离）。
4. 样例实测：`C:\Users\86189\Desktop\给排水智库APP\室外给水设计标准sample.pdf`（1 页、0.19MB、无文字层、单图 1102×1598 ≈135dpi、Indexed 色彩空间）。

## 已确认决策

- **OCR 引擎：PaddleOCR + PP-Structure**（表格多，需表格结构还原；RapidOCR 只识别文字不还原表格结构，不选）。
- **本地离线部署**：企业私有数据不外传，排除云端 OCR API（百度/腾讯/阿里）；环境为 CPU、国内镜像离线。
- **上传上限：80MB**（`MAX_FILE_SIZE = 80 * 1024 * 1024`）。
- **水印黑名单用独立词**（不存整句）：`住房城乡建设部,信息公开,浏览专用`，因斜向两行 OCR 可能拆行/断行，独立词命中更稳。
- **同页文字+表格混合：支持**（PP-Structure 版面分析先行，按区域类型分流，按 bbox.y 排序拼接，是标准场景）。
- 数据库表结构**不变**（`Document`/`DocumentChunk` 复用，`content` 存 OCR 文本），不引入迁移。

## 详细方案（每个改动 + 原因）

### 改动 1：`backend/requirements.txt` 新增 OCR 依赖

```python
# OCR（扫描件识别 + 表格结构还原）
paddlepaddle
paddleocr
```

**原因**：PaddleOCR + PP-Structure（`paddleocr` 包内已含版面分析 + 表格识别）；`paddlepaddle` 为推理后端，必须一起装。
**风险**：paddlepaddle 对 Python 3.12 需 ≥2.6（Windows CPU wheel）；首次运行会联网下载模型（paddle 官方源，国内可达），后续可配离线目录。

### 改动 2：`backend/config.py` 新增 OCR 配置 + 提高上传上限

`Settings` 内新增：

```python
# OCR（扫描件）
OCR_ENABLED: bool = True          # 无文字层时是否走 OCR
OCR_USE_TABLE: bool = True        # 是否启用 PP-Structure 表格识别
OCR_DPI: int = 200                # 渲染 PDF 页为图的分辨率
OCR_WM_THRESHOLD: int = 200       # 浅灰白化阈值：灰度≥此值视为水印→变白
OCR_WM_WORDS: str = "住房城乡建设部,信息公开,浏览专用"  # 水印黑名单（逗号分隔独立词）
OCR_MODEL_DIR: str = ""           # 为空走默认下载；可指向离线模型目录
```

文件末尾常量：

```python
MAX_FILE_SIZE = 80 * 1024 * 1024  # 80MB
```

**原因**：各参数可配置以适配不同深浅水印/分辨率/开关；上传上限是 OCR 链路前置条件（60MB 传不进来无从 OCR）。

### 改动 3：新增 `backend/app/services/ocr_service.py`

职责（纯函数/可 `to_thread`）：

1. `pdf_to_images(path)` — PyMuPDF 每页渲染灰度图（dpi=OCR_DPI）。
2. `remove_watermark(img)` — **浅灰白化**（非硬二值化）：灰度 ≥ 阈值置 255，深色文字与表格线保留。
3. `parse_page(img)` — PP-Structure，返回 `Block`（type: text/title/table/figure + bbox + content）。
4. `table_html_to_markdown(html)` — 表格 HTML（含 colspan/rowspan）→ Markdown 管道表。
5. `reconstruct_list(blocks)` — 正文块按 bbox.y 排序、按 bbox.x 缩进 + 编号正则（`^\d+(\.\d+)*`、`^（\d+）`、`^[a-z）)]`）还原嵌套列表层级。
6. `filter_watermark_text(text)` — 按 OCR_WM_WORDS 剔除水印词/整块水印。
7. `extract_pdf_text(path)` — 入口：渲染→去水印→逐页解析→表格转 Markdown + 列表还原 + 水印过滤，返回每页文本。

**原因**：独立成文件内聚、可独立测试、可 mock（沿用「RAG/向量/模型全 mock」测试约定）；浅灰白化比硬二值化安全（不丢彩色信息/表格线）；表格转 Markdown 保行列结构，避免切 chunk 时拆散。

### 改动 4：改造 `backend/app/services/document_service.py`

仅改 `_load_file` 一个函数，加 PDF 分支：

```python
if ext == ".pdf":
    doc = fitz.open(path)
    if any(page.get_text().strip() for page in doc):   # 有文字层
        doc.close(); return PyMuPDFLoader(path).load()
    doc.close()
    texts = ocr_service.extract_pdf_text(path)          # 扫描件走 OCR
    return [Document(page_content=t) for t in texts]
```

`index_document` 的 `asyncio.to_thread(_load_file, ...)` 不变（OCR 天然被 to_thread 包裹）。

**原因**：有文字层 PDF 仍走原路（快且准，不能全走 OCR）；只改一个函数，下游 `_split_and_annotate`/`_store_chunks`/chapter/clause 提取全复用，改动面最小、状态机不动。
