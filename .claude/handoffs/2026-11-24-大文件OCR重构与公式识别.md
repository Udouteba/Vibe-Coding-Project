## 背景与要解决的问题

1. 上传 25 页扫描件 PDF 触发**前端 60s 超时**（axios `timeout:60000`，而后端同步 OCR 需数分钟）
2. OCR 处理大扫描件时后端**段错误崩溃**（exit 139）
3. 复杂数学公式（分式/根号/上下标/希腊字母）**识别成乱码**
4. 公式识别开启后正文里混入内联 LaTeX 片段（`$d_{\mathrm{j}}$` 等）

## 完成的改动（按主题）

### 1. 上传异步化（治超时）
- `backend/app/api/documents.py`：上传/重索引接口改 `asyncio.create_task` 后台索引，**秒回**（不再同步等待 OCR）
- `frontend/src/views/Knowledge.vue`：上传后提示「后台索引中」+ 每 5s 轮询刷新，直到无 `pending`/`indexing`

### 2. 分批 OCR（治崩溃，核心）
- **根因**：embedding(torch) 与 OCR(paddle) 都是进程级单例，同进程共存触发 OpenMP 运行时冲突 → 段错误
- **方案**：OCR 挪到独立子进程，与 torch 彻底隔离
- 新增 `backend/app/ocr_worker.py`：子进程入口，仅加载 paddle，逐页 OCR 写 jsonl
- `backend/app/services/document_service.py`：`_ocr_via_worker` 子进程分批调度 + `_run_ocr_batch` 轮询进度 + 断点续传
- `backend/config.py`：`OCR_BATCH_SIZE=20` / `OCR_AUTO_SPLIT_THRESHOLD=30` / `OCR_WORKER_TIMEOUT=1800` / `OCR_MAX_RETRY=2`
- 断点续传：每页结果立即 append `uploads/{doc_id}.ocr.jsonl`，崩溃重跑只补缺页；索引成功才清理

### 3. 进度可见
- `backend/app/models/document.py`：加 `total_pages` / `processed_pages`
- `backend/app/main.py`：`_ensure_document_progress_columns` 迁移
- `backend/app/schemas/document.py` + 前端状态列显示「索引中 X/Y 页」

### 4. 公式识别（治公式乱码）
- `backend/app/services/ocr_service.py`：`use_formula_recognition=True` + `parse_page` 加 `formula` 分支（LaTeX 作为独立块保留）
- **踩坑**：`np.asarray(PIL.Image)` 返回只读数组，公式识别要改写图像触发 `ValueError: assignment destination is read-only` → 改用 `np.array`
- 实测：科尔布鲁克/海曾-威廉公式均识别成完整 LaTeX；无公式页 0 个 formula 块，**无误判**

### 5. 内联清洗（治正文 LaTeX 噪声）
- 新增 `backend/app/utils/latex_clean.py`：`clean_inline_latex` 把正文 `$...$` 片段转可读 Unicode（`$d_{\mathrm{j}}$`→`dⱼ`、`$\left(\mathrm{m/s^{2}}\right)$`→`(m/s²)`）
- 关键：**迭代从内到外**消除嵌套花括号（`\mathrm{m/s^{2}}` 单次正则匹配不到）；符号命令后分隔空格一并消费
- `ocr_service.py` 只对非 `formula` 块调用清洗，独立公式保留 LaTeX

### 6. OCR 内存优化
- `ocr_service.py`：`iter_pdf_images` 逐页生成器（原 `pdf_to_images` 一次渲染全部页驻内存），支持 `start_page`/`page_count` 供分批

## 关键实测数据

- OCR 每页约 **60s**（首屏 91s 含引擎加载），25 页 ≈ **25 分钟**（paddle Windows CPU 性能上限）
- 降 DPI（120→80）提速仅 **~15%** 且识别字符降 5~8% → **不值得**，已回退 120dpi
- PP-FormulaNet 模型 728M，走 modelscope 下载（首次）
