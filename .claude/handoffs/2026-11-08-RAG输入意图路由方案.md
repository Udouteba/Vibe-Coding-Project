## 背景与问题

实际对话中用户常有模糊查询（"消防"、"那个水池"）或纯问候（"你好"、"在吗"）。当前直接进检索 + Agent，导致：问候被当成 query 无谓检索、模糊查询检索不准却硬答。

## 已确认方案：LLM 意图分类 + 边界处理

前置用 LLM（复用 DeepSeek）做意图分类，但**分类只做「拦不拦截」，不做「模糊 vs 正常」的精细区分**——模糊查询照常检索，靠检索置信度兜底（避免误伤"短但有效"的查询）。

## 分类设计

| 类别 | 例子 | 路由 |
| --- | --- | --- |
| greeting 问候/寒暄 | "你好"、"在吗"、"谢谢" | 固定礼貌回复，**不检索** |
| off_topic 无关/越界 | "今天天气"、"帮我写代码" | 固定"只回答给排水规范问题"，**不检索** |
| vague 模糊/不完整 | "消防"、"那个水池" | **照常检索**，`low_confidence` 时反问澄清 |
| query 正常查询 | "室外消火栓间距要求" | 正常检索 + Agent |

## 关键设计

1. **分类 prompt 输出结构化 JSON**：`{"category": "greeting|vague|query|off_topic", "clarify": "追问话术(vague 时)"}`。
2. **greeting / off_topic 用固定模板回复**（不调 LLM 生成，省 token、快）。
3. **vague 不前置拦截**：照常检索；检索 `low_confidence`（无结果或最高分 < `RETRIEVE_MIN_SCORE=0.25`）时，用 `clarify` 话术反问用户补充，而非简单"资料不足"。
4. **query 照常**：检索 → Rerank → Agent 生成。

## 改动定位

1. 新增意图分类函数（建议 `app/services/intent_service.py`，或并入 `agent_service.py`）：`ChatOpenAI` 结构化输出分类。
2. `stream_ask`（`agent_service.py:93`）在构建 Agent 前加分类步骤 + 路由：
   - greeting/off_topic → 直接 yield 固定回复，不建 Agent；
   - vague/query → 走现有检索 + Agent。
3. 分类 prompt 独立维护（不混入 SYSTEM_PROMPT）。
4. `low_confidence` 分支升级：vague 时反问澄清（用 `clarify`）。

## 权衡（已确认接受）

- 每次对话多一次 LLM 分类调用（~200–500ms，token 很少）。
- 分类边界有误差（个别模糊/无关可能误判），由「模糊→检索置信度兜底」缓解，不追求 100% 精确。
