## 背景与问题

当前对话模块用**预检索**（`agent_service.py:110`）：检索在 Agent 外一次性完成，结果固化进 `search_regulations` 工具闭包，工具被调用时只返回固化结果（`query` 参数形同虚设，`agent_service.py:44-57`）。

**局限**：实际使用中多轮追问多，预检索无法让模型按追问改写的 query 动态检索（检索 query 被固定为用户原始输入），丧失多轮检索能力。

## 需求

1. 把查询功能做成**真正的 Agent 工具**（工具内部真检索向量库）；
2. Agent **不能回答工具查不到的信息**（检索为空必须答「资料不足」，严禁编造）。

## 已确认决策

1. **引用一致性：全局编号 + 提示词约束**（放弃预检索的"架构保证"，接受可靠性小幅下降）。
2. **每轮工具检索返回 6 条**（沿用 `RETRIEVE_TOP_K=6`）。
3. **需要去重**：按 `document_id + clause + content` 哈希，同一条文不重复编号、不重复进 citations。

## 方案设计

### 工具真检索 + 全局单调编号 + 累积收集

```python
def _make_search_tool(scope_docs):
    collected = []      # 累计所有检索到的条文（去重后），作为 citations
    counter = [0]       # 全局编号，跨多轮调用单调递增
    seen = set()        # 去重集合

    @tool
    def search_regulations(query: str) -> str:
        """根据 query 检索给排水规范条文，返回带编号的条文。"""
        items = rag_service.retrieve(query, scope_docs, k=6)   # 真检索
        if not items:
            return f"未检索到与「{query}」相关的规范条文。"
        parts = []
        for item in items:
            key = (item["document_id"], item["clause"], item["content"])
            if key in seen:
                continue
            seen.add(key)
            counter[0] += 1
            item["cite_id"] = counter[0]
            collected.append(item)
            parts.append(
                f"[{counter[0]}] 《{item['title']}》{item['code']}"
                f"（{item['version']}版）{item['chapter']} {item['clause']}\n{item['content']}"
            )
        return "\n\n".join(parts)

    return search_regulations, collected
```

- `collected`（去重、按 `cite_id` 排序）就是结束后的前端 `citations`。
- 模型正文 `[N]` 靠 prompt 约束「必须用工具返回的 `[N]` 编号引用，不得自行编号」。

### 置信度改为基于累计结果

移除 `stream_ask` 里的预检索 + `compute_low_confidence(retrieved)`，改为 Agent 结束后用 `collected` 计算（无结果或最高分 < `RETRIEVE_MIN_SCORE=0.25` → 低置信度）。

### 「查不到就不答」三层强化

1. **工具空结果信号**：检索为空返回 `"未检索到与「query」相关的规范条文"`；
2. **prompt 硬约束**（在现有 SYSTEM_PROMPT 基础上加严）：
   - 「工具未返回的条文一律不得出现在回答中」；
   - 「工具返回为空时必须回答『资料不足，无法回答』，禁止用自己的知识补充」；
   - 「每个关键结论后用 `[N]` 标注，`[N]` 必须严格对应工具返回的编号，不得自行编号、不得张冠李戴」；
3. **置信度保留**：`low_confidence` 存消息 + `done` 事件，前端告警。

## 改动定位（3 处）

1. `_make_tool`（`agent_service.py:44-59`）：从「返回固化 retrieved」改为「真检索 + 全局编号 + 去重收集」；
2. `stream_ask`（`agent_service.py:93-163`）：移除第 110 行预检索；`scope_docs` 改闭包进工具；置信度改为结束后用 `collected` 计算；
3. `SYSTEM_PROMPT`（`agent_service.py:23-30`）：按上面加严引用 + 不编造约束。

## 取舍说明（如实记录）

- **收益**：模型可用改写 query 动态检索，支持多轮追问（预检索做不到）。
- **代价**：`[N]` 与 citations 的对齐从"架构保证"降级为"全局编号 + prompt 约束"，模型偶有编号不遵守的可能。
- **折中方案（已否，备查）**：第一轮仍预检索保主回答引用稳、工具只做追问增量检索——两套机制，复杂，暂不采用。
